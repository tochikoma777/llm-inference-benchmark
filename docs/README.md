# 文档索引

这个项目的文档分成**五类**，各司其职。想快速了解请按 ★ 顺序读。

| 文档 | 回答什么问题 | 读者 | 更新时机 |
|---|---|---|---|
| ★ [README](../README.md) | 这是什么、怎么跑起来、结论是什么 | 所有人 | 功能或数字变化时 |
| ★ [审计：v0.1 问题清单](audit-v0.1.md) | 原来的实现错在哪、凭什么说它错 | 想复核或接手的人 | 发现新缺陷时（追加，不改历史） |
| ★ [决策记录](decisions.md) | 为什么这样改、放弃了什么 | 维护者、评审者 | 每做出一个架构决策 |
| [路线图与验收](roadmap.md) | 还差什么、下一步做什么、怎么验收 | 维护者 | 完成/新增任务时 |
| [测量方法学](methodology.md) | 每个数字怎么来的、什么条件下会失效 | 引用数据的人 | 口径变化时 |
| [架构说明](architecture.md) | 分层、依赖方向、扩展点 | 贡献者 | 结构调整时 |
| [v0.1 实测存档](reference-run-rtx3090.md) | 最早那批 3090 数据的原始报告 | 想对照历史的人 | 不再更新（历史快照） |

## 文档之间的关系

```
                 ┌──────────────┐
                 │    README    │  入口：是什么 / 怎么用
                 └──────┬───────┘
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
  ┌──────────┐   ┌────────────┐   ┌────────────┐
  │  audit   │──▶│  decisions │──▶│  roadmap   │
  │ 哪里错了 │   │ 为什么这么改│   │ 还差什么    │
  └──────────┘   └─────┬──────┘   └────────────┘
                       │
              ┌────────┴────────┐
              ▼                 ▼
       ┌────────────┐    ┌────────────┐
       │ methodology│    │architecture│
       │ 数字怎么来  │    │ 代码怎么分  │
       └────────────┘    └────────────┘
```

**审计 → 决策 → 路线图** 是一条链：审计提出问题编号（A-xx），
决策引用问题编号说明如何解决（D-xx），路线图记录未解决项与验收方式。

因此：

- 新增一个缺陷 → 在 `audit` 里加 `A-2x`；
- 由它引出的设计选择 → 在 `decisions` 里加 `D-xx`，并在「关联」中回指 `A-2x`；
- 暂不处理的 → 在 `roadmap` 里登记，并说明原因。

## 写作约定

1. **给证据，不给形容词**。写「p99 索引 int(n*0.99) 在 n=100 时取到 max」，
   而不是「p99 算得不准」。
2. **位置必须可定位**。引用旧代码用 `文件:行号 @ v0.1.0`，
   引用新代码用 `路径:行号`，两者都能用 `git show` 复核。
3. **决策要写代价**。只写优点的决策记录等于宣传稿。
4. **不修改已发布的历史条目**。发现写错了就追加一条勘误，保留原始判断。
5. **中文为主，术语保留英文**。`TTFT`、`prefill`、`PagedAttention` 不翻译，
   避免读者在中文与代码之间做二次映射。
6. **每个数字标注来源**。是实测、模拟、还是估算，必须能在文档里找到说明。
